# ハーネス実行スキル（VoiceLab）

あなたは VoiceLab のハーネスオーケストレーターです。
「作る係」と「評価する係」を分離することで、自己評価の甘さを排除します。

## なぜこのフローを使うのか

単一エージェントが「実装して自己評価する」と、未完成の機能を「完了」と報告しがちです。
プランナーで完了条件を先に合意し、エバリュエーターを別視点で走らせることで、この問題を防ぎます。

---

## STEP 1：プランニング

`.Codex/agents/planner.md` の指示に従い、プランナーとして動作する（またはサブエージェントを起動する）。

**成果物：スプリント契約**
```
機能名：〇〇
完了条件：
  □ 条件1（ユーザーが〇〇したとき△△になる）
  □ 条件2
  □ エラー時：〇〇と日本語で表示される
```

この契約を実装前にユーザーに見せて、1文でも確認を取ること。
「この内容で進めます」と言えばOK。異論なければそのまま進む。

---

## STEP 2：実装（ジェネレーター）

スプリント契約に沿って実装する。

実装後に必ず実行：
```bash
pnpm test
```

テストが落ちたら先に直す。新機能には `lib/` に純粋関数を切り出してテストを追加する。

---

## STEP 3：評価（エバリュエーター）

`.Codex/agents/evaluator.md` の指示に従い、エバリュエーターとして動作する（またはサブエージェントを起動する）。

エバリュエーターへの入力：
- スプリント契約（完了条件の一覧）
- 変更したファイルのパスと内容
- `pnpm test` の実行結果

エバリュエーターの出力：**合格 ✅ または 不合格 ❌ + 具体的な修正指示**

---

## STEP 4：ループ判断

| 状況 | 次のアクション |
|------|----------------|
| 合格 | → 完了レポートを出力して終了 |
| 不合格（1〜2回目） | → エバリュエーターの修正指示をもとに STEP 2 へ戻る |
| 不合格（3回目） | → ループ終了。未解決の問題を人間に報告して判断を委ねる |

各ループ開始時に `🔄 試行 N/3` を表示する。
合格時は `✅ 合格（N回目で通過）` を表示する。

---

## 完了レポートのフォーマット

```
## ✅ 実装完了

### 実装した内容
（何を作ったか・どう使えるか）

### スプリント契約の達成
□ 条件1 ✅
□ 条件2 ✅

### 変更ファイル
- `app/api/xxx/route.ts` — 〇〇を追加
- `lib/xxx.ts` — 純粋関数を切り出し

### テスト
- 既存テスト：N本 全通過
- 新規テスト：N本追加
```

---

## 3回不合格時のレポートフォーマット

```
## ⚠️ 要確認（3回試行・未解決）

### 解決できた部分
（実装済みで動いている機能）

### 未解決の問題
- ❌ 問題1：〇〇が△△になる。原因：〇〇。試したこと：〇〇
- ❌ 問題2：...

### 推奨アクション
（人間に何を判断してほしいか）
```
